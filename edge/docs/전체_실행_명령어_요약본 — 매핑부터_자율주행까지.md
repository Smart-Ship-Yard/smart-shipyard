# 1부. 시뮬 (노트북, 개발용)

Gazebo에서 파라미터를 맞춘다. **실물 하드웨어 불필요.**

### ⓪ 다시 띄우기 전 반드시 정리 — 스크립트 한 줄

```bash
~/smart-shipyard/edge/ros2_ws/src/ship_ugv_navigation/scripts/stop_all.sh
```

`✅ 정리 완료 — 남은 프로세스 없음` 이 떠야 다음으로 간다.

**왜 필요한가:** `Ctrl+C` 로 껐어도 자식 노드가 남는다. 남은 `ekf_local` 과
`fake_global_localization` 은 죽은 Gazebo 의 옛 시계로 **얼어붙은 TF** 를 계속
쏜다. 그러면 `Tf has two or more unconnected trees` 가 뜨면서
**Gazebo 에서는 로봇이 움직이는데 RViz 에서는 멈춰 있는** 증상이 나온다.

**왜 스크립트인가 (직접 치지 말 것):** `pkill -f <패턴>` 을 터미널에 여러 줄
붙여넣으면 **그 명령줄 자체가 패턴에 걸려 셸이 스스로를 죽인다.** 그러면 뒤쪽
명령이 실행되지 않아 일부가 살아남는다. 스크립트 안에서는 명령줄이 스크립트
경로뿐이라 이 문제가 없다. 그리고 리눅스는 프로세스 이름을 **15글자까지만**
저장해서 `robot_state_publisher`(21) `controller_server`(17) 같은 것은
`pkill -x` 로 **영원히 안 죽는다.** 스크립트가 이 둘을 다 처리한다.

> 확인은 `ros2 node list` 가 아니라 스크립트 출력으로 한다.
> `ros2 node list` 는 데몬 캐시라 죽은 노드를 한동안 유령으로 보여준다.

### ① 터미널 1 — Gazebo + 로봇 + TF 트리

```bash
cd ~/smart-shipyard/edge/ros2_ws
colcon build --symlink-install --packages-select ship_ugv_description ship_ugv_navigation
source install/setup.bash
ros2 launch ship_ugv_navigation sim_bringup.launch.py
```

### ② 터미널 2 — Nav2 + RViz

```bash
cd ~/smart-shipyard/edge/ros2_ws && source install/setup.bash

# 넓은 곳 기준 (시연장·demo_room) + 순찰
ros2 launch ship_ugv_navigation navigation.launch.py \
  use_sim_time:=true space:=wide map:=demo_room patrol:=true use_rviz:=true

# 좁은 방 기준 (내 방 맵)
ros2 launch ship_ugv_navigation navigation.launch.py \
  use_sim_time:=true space:=narrow map:=shipyard_map_JG_room_v2 patrol:=true use_rviz:=true
```

`patrol:=true` 를 빼면 순찰 없이 Nav2만 뜬다 (RViz 에서 목표를 손으로 찍는 모드).
순찰 원은 `config/patrol_<맵이름>.yaml` 에서 자동으로 읽는다 — 맵 이름 하나가
지도와 순찰 원을 같이 정하므로 좌표를 줄 일이 없다.

`space` 단어 하나로 **4가지가 한 번에** 바뀐다. 설정 파일을 열 일이 없다.

| 항목 | narrow | wide |
|---|---|---|
| local_costmap 크기 | 2×2 m | 5×5 m |
| local·global inflation | 0.10 m | 0.25 m |
| 복구 행동 spin | 미사용 | 사용 |

> `map` 은 **이름만** 넣는다(경로·확장자 불필요). 패키지 `maps/` 안에서 찾는다.
> 노트북과 젯슨의 설치 경로가 같으므로 명령어를 양쪽에서 그대로 쓴다.

### ③ 순찰 상태 보기 / 이벤트 정지·재개

```bash
# 터미널 3 — 순찰 상태 (상태·웨이포인트 번호·바퀴 수)
ros2 topic echo /patrol/status

# 터미널 4 — 이벤트 정지/재개. Step 7 없이도 지금 시험할 수 있다
ros2 topic pub --once /event/active std_msgs/msg/Bool "{data: true}"    # 정지
ros2 topic pub --once /event/active std_msgs/msg/Bool "{data: false}"   # 재개
```

### 목표를 손으로 찍고 싶을 때 (patrol 없이)

RViz 상단 **`2D Goal Pose`** → 지도 빈 곳을 **누른 채 드래그**(방향까지) → 놓기

### 키보드로만 굴려보고 싶을 때 (Nav2 없이)

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p use_sim_time:=true
```

### 눈으로 확인할 것

| 항목 | 정상 |
|---|---|
| 터미널 2 맨 위 배너 | `space` · `행동트리` · `scan_topic` · `cmd_vel 경로` 가 의도대로 |
| 노드 기동 | `Activating` 6개 후 조용해짐. **ERROR 없음** |
| RViz Displays 목록 | **12개** (Grid ~ Odometry) |
| 로봇 3D 모델 | 차체 진회색 · 바퀴 검정 · **앞쪽에 빨간 라이다** |
| 라이다 빨간 점 | 방 벽 모양. **로봇을 몰아도 제자리 고정** |
| footprint (초록) | 앞으로 길쭉한 직사각형. **바퀴축이 뒤에서 20 % 지점** |
| 벽 주변 팽창 띠 | wide 25 cm / narrow 10 cm — 눈에 띄게 다름 |
| 목표 찍은 직후 | **파란 선**(전역 경로) + 로봇 앞 **주황 점**(추종 목표) |
| 도착 | 목표 **15 cm** 안에서 정지 |
| 순찰 (`patrol:=true`) | 로봇이 중앙 대상 주위를 **시계방향**으로 계속 돎. 약 2분에 한 바퀴 |
| 순찰 로그 | `웨이포인트 N 도달 -> 다음 N+1` 이 이어지고 `★ 1바퀴 완료` |
| 이벤트 정지 | `true` 주면 **즉시** 멈춤, `/patrol/status` 의 `state` 가 `STOPPED` |
| 이벤트 재개 | `false` 주면 다시 출발, `state` 가 `RUNNING` |

**정상인데 뜨는 것**

| 현상 | 이유 |
|---|---|
| 시작 직후 `Timed out waiting for transform` | TF 버퍼가 차기 전. 곧 멈춤 |
| 주행 중 `detected collision ahead` 가 자주 | 컨트롤러가 앞을 예측해 미리 멈추는 것. 목표엔 도달한다 |
| `Control loop missed its desired rate` 가끔 | 부하 순간. 무시 |
| `No goal checker was specified` 한 번 | 하나뿐인 것을 자동 선택한다는 안내 |
| **노란 선(충돌예측)이 거의 안 보임** | 원래 점 2개짜리 짧은 궤적이라 그렇다. 결함 아님 |
| 주행 중 새 목표를 주면 5초 멈춤(`Wait`) | 옛 경로가 무효가 되어 복구가 한 번 도는 것. 곧 새 경로로 간다 |

```bash
ros2 run tf2_tools view_frames             # TF 트리 그림 파일 생성
ros2 topic hz /clock                       # 100 Hz 여야 함 (10이면 타이머가 잘림)
ros2 topic hz /odometry/local              # 50 Hz (ekf_local)
ros2 topic hz /scan                        # 10 Hz (라이다)
ros2 topic echo /odometry/global --once    # 절대 위치 나오나
```

# 2부. 실물 매핑 (젯슨)

상세 절차·주의사항은 [재매핑_체크리스트.md](재매핑_체크리스트.md). 여기는 명령어만.

```bash
# 터미널 1 — 센서·EKF·TF 전부. ★ 시연 끝날 때까지 끄지 않는다 ★
ros2 launch ship_ugv_localization localization.launch.py

# 터미널 2 — 직진/회전 명령용 (키보드 조종과 동시 실행 금지)
ros2 launch ship_ugv_motion_control motion_control.launch.py

# 터미널 3 — UWB 캘리브레이션. 두 줄을 연달아 실행
ros2 service call /uwb_map_calibration/calibrate std_srvs/srv/Trigger
ros2 topic pub --once /motion/move_distance std_msgs/msg/Float64 "{data: 1.5}"
#   ★ 터미널 1 로그에서 [캘리브레이션 성공] 을 눈으로 확인할 것
#     (서비스 응답의 success: True 는 "수집 시작"일 뿐 성공이 아니다)
ros2 run tf2_ros tf2_echo map uwb_frame        # 0,0,0 이 아니면 성공

# 터미널 2 — 모션 컨트롤 Ctrl+C 후 매핑 시작
ros2 launch ship_ugv_localization mapping.launch.py

# 터미널 4 — 키보드 주행. 중앙 물체 주위를 완전한 한 바퀴 이상, 방 전체를 천천히
ros2 run ship_ugv_motion_control keyboard_teleop_node

# 터미널 3 — UWB 좌표계와 SLAM 좌표계 정합. inlier 40% 이상 확인
ros2 service call /slam_map_alignment/align std_srvs/srv/Trigger

# 터미널 3 — 맵 저장
cd ~/smart-shipyard/edge/ros2_ws/src/ship_ugv_navigation
ros2 run nav2_map_server map_saver_cli -f maps/shipyard_map_<장소>_v<버전번호>

# ★★ 저장 직후 터미널 2의 mapping.launch.py 를 Ctrl+C 로 끌 것 ★★
#    안 끄면 slam_toolbox가 /map을 계속 발행해 Nav2 map_server와 충돌한다
#    터미널 1(localization)은 그대로 켜둔다

# 터미널 3 — 좌표 보정 + free_thresh 교정 + 순찰 가능 검사 (ROS 불필요)
python3 scripts/finalize_map.py shipyard_map_<장소>_v<버전번호>
#   출력되는 center_x / center_y / radius 를 순찰 노드 파라미터에 넣는다

# 터미널 3 — 결과 공유
cd ~/smart-shipyard && git add edge/ros2_ws/src/ship_ugv_navigation/maps/
git commit -m "map: shipyard_map_<장소>_v<버전번호>" && git push
```

# 3부. 실물 자율주행 (젯슨) — Step 5·6·7 완성 후

```bash
# 터미널 1 — 2부에서 켠 그대로. 다시 켤 필요 없다
#   (재부팅했다면 localization.launch.py 부터 캘리브레이션까지 다시)

# 터미널 2 — Nav2. 시연장 넓이에 맞춰 space 만 고른다
ros2 launch ship_ugv_navigation navigation.launch.py \
    space:=wide map:=shipyard_map_<장소>_v<버전번호> patrol:=true
```

시뮬과 달라지는 것은 **두 가지뿐이고 둘 다 자동**이다.

| | 시뮬 | 실물 |
|---|---|---|
| `use_sim_time` | `true` 로 준다 | 생략(기본 false) |
| 라이다 토픽 | `/scan` | **`/scan_filtered`** ← `use_sim_time` 보고 자동 선택 |

기동 로그 맨 위 배너에서 `scan_topic : /scan_filtered` 인지 **반드시 확인**할 것.
`/scan` 이면 후방 180도가 안 잘려 차체 뒷부분이 장애물로 찍힌다.

시연 중 확인·조작:
```bash
ros2 topic echo /patrol/status                             # 순찰 상태·웨이포인트 번호
ros2 topic echo /event/active                              # 정지 여부 (true=정지)
ros2 topic pub --once /event/ack std_msgs/msg/Empty "{}"   # 수동 재개 (폴백)
```
