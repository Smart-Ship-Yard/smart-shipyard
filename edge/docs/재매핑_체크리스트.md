# 0단계 ★ 바닥 준비

> **왜 추가했나:** 첫 매핑(v1)이 실패한 원인이 매핑 품질이 아니라 **공간 부족**이었다.
> 미탐사 영역을 전부 빈 바닥으로 가정하고 다시 계산해도 결과가 같았으므로,
> 원인은 실제 벽·가구다. **바닥을 안 치우면 몇 번을 다시 떠도 똑같다.**

- [ ] 방에서 **제일 트인 자리**를 고른다
- [ ] 그 자리를 중심으로 **지름 1.2 m 원**(또는 1.2 × 1.2 m 사각형) 안을 완전히 비운다
      → 바닥에 테이프로 표시해두면 확인하기 쉽다
- [ ] **중앙 물체를 세워서** 정중앙에 놓는다

      ⚠️ **눕히면 안 된다.** 라이다는 지면 0.20 m 높이의 **평면 하나만** 스캔한다.
      눕힌 폼롤러는 높이가 0.127 m라 그 평면 아래에 있어 **아예 안 잡힌다.**
      맵에도 안 찍히고 주행 중에도 안 보여서 로봇이 밟고 지나간다.
      → 물체 높이가 0.20 m를 넘지 않으면 **받침대를 써서 라이다 높이에 걸치게** 한다.
        받침 높이 = 0.20 − (물체 높이 ÷ 2). 단 **받침은 물체보다 작아야 한다**
        (받침이 더 넓으면 라이다에 안 보이는 부분에 로봇이 부딪힌다).

- [ ] **캘리브레이션 시작점과 1.5 m 끝점, 두 곳에 테이프**를 붙인다

      > **왜:** 캘리브레이션이 성공하면 **로봇이 서 있던 자리가 map 원점 (0,0)**,
      > **직진한 방향이 map +x축**이 된다. 방 구조와 무관하게 로봇 위치가
      > 좌표계를 정의한다. 다음에 이 맵을 재사용하려면 **같은 자리·같은 방향**에서
      > 캘리브레이션해야 한다. 점 하나만 찍으면 방향을 재현할 수 없어서 두 점을 찍는다.
      > 방향이 5°만 틀어져도 2.5 m 떨어진 지점에서 22 cm 어긋난다.

- [ ] **앵커를 고정한다.** 매핑 후 앵커를 옮기면 이 맵은 무효다.

# 필수 사전 지식 ★ 3가지

이걸 모르면 실패해도 실패한 줄 모른다.

### ① `success: True`는 캘리브레이션 성공이 아니다

`/uwb_map_calibration/calibrate` 서비스가 돌려주는 `success: True`는
**"수집을 시작했다"**는 뜻일 뿐이다. 진짜 결과는 로봇이 1 m를 지난 뒤
**터미널 1 로그**에 `[캘리브레이션 성공]` / `[캘리브레이션 실패]`로 나온다.
**반드시 그 줄을 눈으로 확인한다.**

### ② 캘리브레이션 노드를 끄면 안 된다

`uwb_map_calibration` 노드가 `map→uwb_frame` TF의 **유일한 발행자**다.
Ctrl+C나 `pkill`로 끄면 TF가 사라지고, `slam_map_alignment`가 UWB 샘플을
전부 버려서 나중에 `align`이 데이터 부족으로 실패한다.
이 노드는 `localization.launch.py` 안에 있으므로 **터미널 1을 건드리지 않는다.**

### ③ 캘리브레이션은 1 m를 채우면 자동으로 끝난다

```
최소 1.0 m 이동 시 자동 종료 / 최대 30초 타임아웃
```
1.5 m 직진은 약 10초 걸리므로 여유 있다.

### ★ 주행 방법 — v1 실패의 직접 원인이었던 부분

> **왜 중요한가:** 중앙 물체 주위를 한 바퀴 완전히 돌지 않으면
> 자유공간이 **고리(ring)를 이루지 못한다.** 그러면 순찰 경로가
> 아예 생성되지 않는다. v1 맵에서 실제로 이 문제가 났다.

- [ ] **중앙 물체 주위를 완전한 한 바퀴 이상** 돈다 ← 가장 중요
- [ ] 반지름을 바꿔가며 **2~3바퀴** (안쪽 한 바퀴, 바깥쪽 한 바퀴)
- [ ] 중앙뿐 아니라 **방 바닥 전체를 훑는다**
      (안 지나간 곳은 미탐사로 남고, 최종적으로 주행 불가 영역이 된다)
- [ ] **천천히** 움직인다 (스캔 매칭이 따라올 시간을 준다)
- [ ] 같은 곳을 다시 지나가 루프 클로저를 유도한다
- [ ] 방향(시계/반시계)은 **아무래도 상관없다.** 양방향으로 돌면 오히려 좋다

중간 확인 (터미널 5):
```bash
ros2 topic hz /map
```
`average rate: 0.5` (2초에 1번)이면 매핑이 정상 동작 중이다.

## 7단계. UWB 맵과 SLAM 맵 좌표 일치 — 터미널 3

```bash

```

| 항목 | 통과 기준 |
|---|---|
| `success` | `True` |
| `대응점` | 10개 이상 (수십~수백이면 좋음) |
| `inlier 비율` | **40% 이상** (70% 넘으면 좋음) |

RViz에서 fixed frame을 `map`으로 했을 때 로봇이 화면 중앙에 있으면 정상.
(로봇 좌표축이 몇 cm씩 떠는 것은 UWB 노이즈로 **정상**이다. 매핑에는 영향 없다.)

## 9단계 ★ 마무리 — 명령 하나

```bash
python3 scripts/finalize_map.py shipyard_map_v3
```

**이 한 줄이 4가지를 자동으로 처리한다:**

1. **정합·캘리브레이션 기록을 레포로 복사**
   슬램 노드들이 결과 json을 `/tmp`에 저장하는데 `/tmp`는 재부팅 시 삭제된다.
   파일명에 맵 이름을 붙여 저장하므로 다음 매핑 때 덮어쓰이지 않는다.
   (`/tmp`가 지워지면 노드의 번호 카운터가 001부터 다시 시작하기 때문)

2. **맵 `origin`을 map 좌표계로 보정** ← 이게 가장 중요하다

   > **왜 필요한가:** slam_toolbox는 이 프로젝트 규칙상 map_frame을 `slam_map`으로 쓴다.
   > `map_saver_cli`는 TF를 적용하지 않고 `/map` 토픽 값을 **그대로** 파일에 쓰므로
   > **저장된 맵은 `slam_map` 좌표계**다. 반면 Nav2와 EKF는 `map` 좌표계로 동작한다.
   > RViz에서 정상으로 보이는 건 RViz가 TF를 실시간 적용하기 때문이고, 파일엔 반영이 안 된다.
   >
   > **v2 실측: 0.94 m 이동 + 138° 회전 차이.** 보정 안 하면 지도가 138도 돌아간 채로
   > 인식되어 완전히 사용 불가다.
   >
   > 보정은 `align_*.json`의 θ, tx, ty를 yaml `origin`에 합성하는 것이다.
   > `origin`의 세 번째 값이 yaw라서 **이미지를 다시 그릴 필요가 없다.**
   > 공식은 장소·UWB 배치와 무관하게 항상 같고, 바뀌는 건 숫자 세 개뿐이다.

3. **`free_thresh`를 0.196으로 교정**

   > **왜 0.196인가 (튜닝값이 아니라 상수다):**
   > PGM에서 미탐사 픽셀은 205이고 점유확률은 (255−205)/255 = **0.19608**이다.
   > `map_saver_cli`가 쓰는 기본값 0.25로 두면 0.19608 < 0.25 이므로
   > **미탐사 영역이 전부 "자유공간"으로 분류되어 Nav2가 매핑 안 된 곳으로 경로를 뽑는다.**
   > 0.196이면 0.19608 > 0.196 이라 미탐사가 미탐사로 남는다.
   > **방 크기와 무관하게 항상 0.196이다.** 205라는 인코딩이 안 바뀌기 때문.

4. **순찰 가능 여부 검사**
   로봇 실측 footprint로 반지름별 원을 훑어 완주 가능 여부를 판정한다.

### 결과 읽는 법

```
✅ 순찰 가능 (여유 충분)          → 그대로 사용
🟡 사용 가능하지만 여유가 빠듯     → 사용 가능. inflation_radius를 0.10 m로
❌ 완주 가능한 반지름이 없다       → 바닥을 더 치우고 재매핑
```

성공하면 이렇게 출력된다:

```
   patrol_mission_node 파라미터에 넣을 값:
     center_x: 3.457
     center_y: 0.543
     radius:   0.30
```

**이 세 숫자를 순찰 노드 파라미터에 넣으면 매핑 작업은 끝이다.**

# 문제해결

## A. `샘플 부족` — UWB가 안 나옴

```bash
ros2 topic hz /uwb/pose          # 9~10 Hz 나와야 정상
ls -l /dev/uwb_tag /dev/ttyACM*  # udev 심볼릭 링크 살아있나
```
`/uwb/pose`가 안 나오면 USB를 다시 꽂거나 앵커 전원을 확인한다.
앵커가 3개 이상 잡혀야 좌표가 나온다.

## B. `Message Filter dropping message: frame 'laser'` 가 계속 반복

라이다 스캔이 TF로 변환되지 않아 **맵이 아예 안 그려지는 상태**다.
시작 직후 한두 번은 정상이므로 **10초 이상 반복될 때만** 문제로 본다.

```bash
ros2 topic hz /map               # 0.5 Hz 안 나오면 매핑 안 되는 중
ros2 topic hz /scan_filtered     # 라이다가 살아있나
ros2 run tf2_ros tf2_echo base_link laser
```

## C. `'map'<-'uwb_frame' TF 조회 실패`

**가장 위험한 경고.** `slam_map_alignment`가 UWB 샘플을 **전부 버리는 중**이라
나중에 `align`이 데이터 부족으로 실패한다. 경고는 5초에 한 번만 떠서
조용해 보이지만 그동안 계속 버리고 있다.

원인은 거의 항상 **캘리브레이션 노드가 죽은 것**이다 (Ctrl+C 또는 pkill).

```bash
ros2 node list | grep calib               # 노드 살아있나
ros2 run tf2_ros tf2_echo map uwb_frame   # 값이 출력되면 TF 존재
```

죽었으면 새 터미널에서 되살린다 (이 터미널도 끝까지 열어둔다):
```bash
ros2 run uwb_map_calibration calibration_node
```

⚠️ **TF가 없던 동안 주행한 구간은 대응점이 안 쌓였다.**
TF 복구 후 **5단계부터 다시 매핑**할 것 (로컬라이제이션은 살려둔 채로).

## D. `finalize_map.py` 가 정합 기록을 못 찾음

```
❌ 정합 기록을 못 찾았다: /tmp/slam_map_alignment_results/align_*.json
```

7단계(align)를 안 했거나, 젯슨을 재부팅해서 `/tmp`가 지워진 것이다.
align을 다시 호출하면 된다 (매핑 노드가 아직 떠 있어야 한다).

이미 레포에 기록이 있다면:
```bash
python3 scripts/bake_map_origin.py maps/shipyard_map_v3.yaml \
    --align maps/calibration_records/align_shipyard_map_v3.json
```

값을 직접 넣을 수도 있다 (`tf2_echo map slam_map` 출력):
```bash
python3 scripts/bake_map_origin.py maps/shipyard_map_v3.yaml --tf <x> <y> <yaw>
```

# 참고

- **UWB 앵커를 재배치하면** 캘리브레이션과 align을 재실행하고 **맵을 다시 떠야 한다.**
- **저장된 맵을 다음 세션에 재사용하려면** 테이프 표시한 자리·방향에서
  캘리브레이션을 다시 하고, 앵커는 그대로 두어야 한다.
- `align_*.json` / `calib_*.json` 은 **슬램 노드가 스스로 저장하는 기록**이다
  (`_save_result()`). 저장 위치 `/tmp`도 그쪽 코드의 기본값
  (`result_save_dir` 파라미터)이며, 우리는 결과물을 복사해 갈 뿐이다.
  **그쪽 파일을 수정하지 않으므로 PR 충돌 위험이 없다.**
