# 이벤트 중복 제거 · 치워짐 확인 튜닝 가이드

`change_point_detector`(`edge/ros2_ws/src/ship_ugv_perception/ship_ugv_perception/change_point.py`)의
파라미터를 언제 어떻게 바꿔야 하는지 적어둔다. **순찰 반지름을 바꿀 때 반드시 이 문서를 볼 것.**
두 값이 서로 묶여 있어서, 한쪽만 바꾸면 조용히 깨진다.

작성: 2026-08-24 (실물 테스트 중 사고 5건을 겪고 정리)

---

## 1. 요구사항 (이게 기준이다)

| # | 동작 |
|---|---|
| ① | 불을 처음 인식하면 정지 + 프론트 팝업 + 핑 |
| ② | 확인 후 재개, **같은 자리에 그대로 있으면 다시는 정지하지 않는다** |
| ③ | 배에 가려 안 보이는 구간이 있어도 **핑은 계속 유지된다** |
| ④ | **불이 자리를 옮겼을 때만** 다시 정지한다 |
| ⑤ | 옮기면 이전 자리 핑은 지우고, 새 자리에 새 핑을 찍는다 |

---

## 2. 3단 구조

```
yolo_depth_publisher          검출 (u, v, depth) — 화면좌표
        │  /event_detection/uvd
        ▼
change_point_detector         map 좌표 변환 + 중복 제거 + 치워짐 확인
        │  /event_detection/map_point      (새 이벤트만)
        │  /event_detection/cleared        (치워짐 확인)
        ▼
event_gate_node (정지)  ·  websocket_client (서버 전송)
```

**중요:** `event_gate_node` 와 `websocket_client` 는 원본 `/uvd` 를 보지 않는다.
반드시 `change_point_detector` 의 출력만 본다. 이게 안 지켜지면 중복 제거가
통째로 무력화된다 (2026-08-21 사고, 커밋 d025420).

---

## 3. 파라미터

| 파라미터 | 현재값 | 역할 |
|---|---|---|
| `dedup_radius_m` | 0.5 m | 이 반경 안이면 "같은 이벤트" — 재발행 안 함 (② ④를 가름) |
| `event_ttl_s` | 600 s | 이만큼 재검출 없으면 목록에서 잊는다 |
| `clear_radius_m` | 2.0 m | 이 거리 안이어야 치워짐 판정 대상 |
| `clear_watch_s` | **60 s** | 이만큼 연속으로 안 보이면 "치워졌다" (③ ⑤를 가름) |
| `min_event_age_s` | 10 s | 이벤트가 이만큼 늙어야 치워짐 판정 시작 |
| `min_confidence` | 0.5 | 이 미만 검출은 무시 |

이 노드는 **파라미터 변경 콜백이 없다.** `ros2 param set` 은 안 먹힌다.
값을 바꾸려면 코드를 고치고 `colcon build` 후 노드를 재시작해야 한다.

## 4. ★ 핵심 규칙 — `clear_watch_s` 는 "배가 가리는 시간"보다 길어야 한다

### 왜

순찰 원의 **중심에 배가 있다.** 로봇이 배 반대편으로 돌면 배가 불을 가려서
검출이 끊긴다. 그런데 `in_camera_fov()` 는 "카메라가 그 방향을 향하는가"만
각도로 계산할 뿐 **가림(occlusion)은 모른다.** 그래서 각도상 FOV 안이라
게이트를 통과하고, 검출이 없으니 "치워졌다"고 오판한다.

가림과 진짜 없어짐은 **더 긴 시간으로만 구분된다:**

- 가려진 것 → 다음 바퀴에 **반드시** 다시 보인다
- 치운 것 → 영영 안 보인다

### 실측 (2026-08-24 20:53, 반지름 1.00 m)

```
20:53:20 ~ 20:53:40   fire 59건 검출 (최대 공백 1.00초)  ← 잘 보임
20:53:40              검출 끊김 — 배 뒤로 들어감
20:54:10              검출 재개
  => 가림 구간 약 30초, 한 바퀴 약 50초 (가림 비율 60%)
```

`clear_watch_s = 5` 였을 때 한 바퀴마다 오판이 났고, 그때마다 이벤트가
목록에서 빠져 같은 불이 새 이벤트로 재등록되며 **재정지**했다:

```
20:53:20  fire@0.37,-1.12  등록
20:53:48  cleared          (불은 그대로 있는데 판정됨)
20:54:10  fire@0.40,-1.12  3.5cm 옆에 재등록 → 재정지
20:54:45  cleared ... 무한 반복
```

### 규칙

```
clear_watch_s  >  가림 시간 × 2
가림 시간      ≈  한 바퀴 시간 × 0.6
한 바퀴 시간    =  2πR / v          (R = 순찰 반지름, v ≈ 0.126 m/s 실측)
```

### 반지름별 표 (실측 속도 0.126 m/s 기준)

| 순찰 반지름 | 한 바퀴 | 가림 시간 | `clear_watch_s=60` 여유 |
|---|---|---|---|
| 0.60 m | 30 초 | 18 초 | 3.3 배 ✅ |
| 0.80 m | 40 초 | 24 초 | 2.5 배 ✅ |
| **1.00 m (현재)** | **50 초** | **30 초** | **2.0 배** ✅ |
| 1.10 m | 55 초 | 33 초 | 1.8 배 ⚠️ |

**반지름을 줄이면 `clear_watch_s` 는 안 건드려도 된다** — 한 바퀴가 짧아져
가림 시간도 같이 줄고, 여유는 오히려 늘어난다.

**반지름을 키우거나 로봇을 느리게 하면 반드시 다시 계산할 것.** 둘 다 한 바퀴
시간을 늘려 가림 시간을 늘린다. 이 맵(`shipyard_map_hall_v6`)에서 쓸 수 있는
반지름 상한은 1.00 m 이고(마스크 하한 0.80, 벽 여유 상한 ~1.10), 1.10 을 쓰려면
`clear_watch_s` 를 70~80 초로 올리는 게 안전하다.

### 대가

불을 **진짜로** 치웠을 때 프론트 핑이 사라지기까지 최대 1분쯤 걸린다.
이건 의도한 트레이드오프다 — "가려졌다고 핑이 깜빡 사라지는 것"이 훨씬 나쁘다.

## 5. `dedup_radius_m` — 하나의 반경이 두 요구를 겸임한다

이 값 하나가 상충하는 두 요구를 동시에 만족시켜야 한다:

- **크게** → "각도 바뀌어도 같은 불로 봐라" (② 유리)
- **작게** → "옮기면 다른 불로 봐라" (④ 유리)

### 변천사 (전부 실측 근거)

| 값 | 결과 |
|---|---|
| 0.5 | 초기값 |
| 1.0 (커밋 8428374) | **오진이었다.** "각도 바뀌면 재등록" 을 고치려 키웠는데, 실제 원인은 clear 오판이 목록에서 먼저 지운 것이었다 (재등록 좌표가 14cm 차이라 0.5로도 매칭됐을 거리) |
| 0.0 (커밋 d81c9b7) | 데모 당일 임시 비활성화 |
| **0.5 (현재)** | 근본 원인(clear 오판)이 해결돼 되돌림 |

**1.0 이 낸 실제 피해:** 불을 0.9 m 옮겼는데 1.0 m 반경 안이라 "같은 불"로
매칭돼 정지도 팝업도 안 떴다. **테스트할 때 `dedup_radius_m` 보다 확실히 멀리
옮길 것** (0.5 이면 최소 0.7 m 이상 권장).

### 근본 해결 (미완)

위치 오차는 거리에 비례한다 (`오차 ≈ depth × tan(헤딩오차)`). 그래서 고정
반경이 아니라 **거리 비례 동적 반경**이 맞다. `_estimate_position_uncertainty()`
가 그 자리인데 지금은 `return 0.15` 고정값 placeholder 다. 시간 생기면 여기를
실제로 구현하고 `dedup_radius` 를 이벤트마다 계산할 것.

## 6. 그 밖에 겪은 사고와 현재 방어

| 사고 | 원인 | 방어 |
|---|---|---|
| 핑이 반짝하고 꺼짐 | 보고 직후 판정 시작 | `min_event_age_s` 10초 |
| 카메라가 등 돌린 구간을 "봤다"로 셈 | clear 가 거리만 봄 | `in_camera_fov()` 게이트 |
| 관찰 끊긴 시간이 watch 에 섞임 | FOV 밖에서도 벽시계가 감 | FOV 밖이면 `range_entered_at` 리셋 |
| 저신뢰도 1프레임 오탐이 정지시킴 | confidence 필터 없음 | `min_confidence` 0.5 |
| clear 가 영영 발동 못 함 | `has_left_once` 가 순찰 기하 의존 | 나이 조건으로 대체 |
| 불 옮겨도 무반응 | 화면좌표 기준 영구 기억 | `yolo_depth_publisher` 의 `reported_tids`/`reported_fallbacks` 제거 |

## 7. 검증

순수 함수 테스트 (ROS 없이 돌아간다):

```bash
cd ~/smart-shipyard/edge/ros2_ws/src/ship_ugv_perception
python3 test/test_change_point_clear.py
```

실물 확인 순서:

1. 불 놓기 → 정지 + 팝업 + 핑
2. 확인 누르고 재개 → **몇 바퀴를 돌아도 재정지 없어야 함**, 핑도 유지
3. 불을 0.7 m 이상 옮기기 → 정지 + 새 핑
4. 불 완전히 치우기 → 약 1분 뒤 핑 사라짐 (`event_cleared`)

DB 확인:

```bash
curl -s http://192.168.0.5:8000/api/history | python3 -m json.tool
```

`event_cleared` 가 DB 에 안 쌓이면 백엔드가 옛날 코드다 —
`backend/main.py` 의 `LOGGED_EVENT_TYPES` 에 `EVENT_CLEARED` 가 있는지 볼 것.
