# 이벤트 발생 시 로봇 정지 / 관제 확인 시 재개

2026-08-07 · 백엔드·Nav2 담당(이정기)

---

## 무엇을 만드나

위험 이벤트(**화재 · 낙상 · 안전모 미착용**)가 감지되면 **로봇이 그 자리에 멈춰서**
관제로 상황을 보여주고, 관제자가 **"확인"을 누르면 다시 순찰**을 시작한다.

```
이벤트 감지 → 로봇 정지 → 관제 팝업 → "확인" 클릭 → 순찰 재개
```

**"해결"이 아니라 "확인"입니다.**
불 끄는 데는 오래 걸리는데 그동안 로봇이 묶여 있으면 다른 위험을 못 찾습니다.
관제자가 "봤다"고만 알려주면 로봇은 순찰을 계속합니다.
→ 버튼 라벨도 **"확인"** (처리 완료 ❌)

**위험물이 안 치워졌으면 다음 바퀴에 또 알립니다.** (약 40초마다)
아직 처리 안 됐다는 뜻이므로 의도된 동작이고, 그때마다 "확인"을 다시 누르면 됩니다.

## 각자 할 일

**새 서버 주소도, 새 연결도 없습니다.** 지금 쓰는 웹소켓 그대로입니다.

| 담당 | 할 일 |
|---|---|
| 백엔드 (정기) | ✅ 완료 |
| 프론트 (명재) | 버튼 1개 |
| 젯슨 (주현) | 수신 루프 (~10줄) |

### 🖥️ 프론트엔드 — 명재

이벤트 팝업에 **"확인" 버튼**을 추가하고, 누르면 **지금 쓰는 소켓**(`/ws/frontend`)으로
이 한 줄만 보내주세요.

```json
{"event_type": "event_ack"}
```

- `webrtc_signal` 보내는 그 소켓 그대로 — 새 연결·새 API 없음
- 서버가 젯슨으로 전달합니다 (완료)
- 응답 기다릴 필요 없음. 보내고 팝업 닫으면 끝

### 🤖 젯슨 — 주현

`ship_ugv_perception/websocket_client.py`가 지금 **송신만** 하는데,
**수신 루프**를 추가해서 받은 메시지를 **해석하지 말고 그대로** 토픽으로 발행해주세요.

```
토픽: /server/inbound
타입: std_msgs/String     (받은 JSON 문자열 그대로)
```

- 내용 판단은 Nav2 노드가 합니다
- 서버→젯슨 메시지가 늘어나도 이 통로 하나로 처리되니 재작업 없음
- 기존 송신 로직·욜로 쪽은 **손댈 것 없음**
