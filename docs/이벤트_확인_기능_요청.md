# 이벤트 발생 시 로봇 정지 / 관제 확인 시 재개

2026-08-07 · 백엔드·Nav2 담당(이정기)

---

위험 이벤트(화재 · 낙상 · 안전모 미착용)가 감지되면 로봇이 그 자리에 멈춘다.
**프론트엔드**는 자동으로 뜨는 이벤트 팝업에 "확인" 버튼을 달고, 누르면 확인 메시지를
서버로 보낸다. **서버**는 그 메시지를 젯슨으로 전달한다. **젯슨**은 그 메시지를 받을
수신 루프를 만들어 ROS 토픽으로 흘려보낸다. 그러면 **Nav2**가 그걸 받아 순찰을 재개한다.

새 서버 주소도, 새 연결도 없다. 지금 쓰는 웹소켓 그대로다.
서버 쪽 작업은 완료됐다.

---

## 🖥️ 프론트엔드 — 명재

이미 있는 위험 이벤트 자동 팝업(`CctvPopup`)에 **"확인" 버튼**을 추가하고,
누르면 **지금 쓰는 소켓**(`/ws/frontend`)으로 이 한 줄만 보내주세요.

```json
{"event_type": "event_ack"}
```

- `webrtc_signal` 보내는 그 소켓 그대로 — 새 연결·새 API 없음
- 버튼을 누르면 메시지 전송 + 팝업 닫기 (지금 Esc가 하는 일에 전송만 추가)
- 서버가 젯슨으로 전달합니다 (완료)
- 응답 기다릴 필요 없음
- 위험물이 안 치워졌으면 다음 바퀴(약 40초 뒤)에 팝업이 다시 뜹니다 — 의도된 동작

## 🤖 젯슨 — 주현

`ship_ugv_perception/websocket_client.py`가 지금 **송신만** 하는데,
**수신 루프**를 추가해서 받은 메시지를 **해석하지 말고 그대로** 토픽으로 발행해주세요.

```
토픽: /server/inbound
타입: std_msgs/String     (받은 JSON 문자열 그대로)
```

- 내용 판단은 Nav2 노드가 합니다
- 서버→젯슨 메시지가 늘어나도 이 통로 하나로 처리되니 재작업 없음
- 기존 송신 로직·욜로 쪽은 손댈 것 없음
