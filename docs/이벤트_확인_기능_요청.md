# 이벤트 발생 시 로봇 정지 / 관제 확인 시 재개

2026-08-07 · 백엔드·Nav2 담당(이정기)

---

## 무엇을 만드나

위험 이벤트(**화재 · 낙상 · 안전모 미착용**)가 감지되면 **로봇이 그 자리에 멈춰서**
관제로 상황을 계속 보여주고, 관제자가 **"확인"을 누르면 다시 순찰**을 시작한다.

```
이벤트 감지  →  로봇 정지  →  관제 팝업  →  "확인" 클릭  →  순찰 재개
```

## ★ "해결"이 아니라 "확인"입니다

실제로 불을 끄는 데는 오래 걸리는데, 그동안 로봇이 묶여 있으면
**다른 위험을 못 찾습니다.** 관제자가 "봤다"고만 알려주면 로봇은 순찰을 계속합니다.

→ 그래서 버튼 라벨도 **"처리 완료"가 아니라 "확인"** 입니다.

## 현재 상태

| | 상태 |
|---|---|
| 백엔드 | ✅ **완료** (상수 2줄 추가, 중계 로직은 기존 것 그대로) |
| 프론트 | 버튼 1개 추가 필요 |
| 젯슨 | 수신 루프 추가 필요 |

**새 서버 주소도, 새 연결도 없습니다.** 지금 쓰는 웹소켓 그대로입니다.

# 🖥️ 프론트엔드 (명재)

이벤트 알림 팝업에 **"확인" 버튼** 하나만 추가해주세요.

누르면 **지금 쓰는 웹소켓**(`/ws/frontend`)으로 이 한 줄만 보내면 끝입니다.

```json
{"event_type": "event_ack"}
```

- 새 연결이나 새 API 없음 — `webrtc_signal` 보내는 그 소켓 그대로
- 서버가 알아서 젯슨으로 전달합니다 (백엔드 작업 완료)
- 응답 기다릴 필요 없음. 보내고 팝업 닫으면 됩니다
- 버튼 라벨은 **"확인"** (해결/처리완료 아님)
- 부가 정보(어떤 이벤트인지 등)를 같이 넣어도 젯슨까지 그대로 전달됩니다

# 🤖 젯슨 (주현)

`ship_ugv_perception/websocket_client.py`가 지금 **송신만** 하고 있는데,
**수신 루프**를 추가해주세요.

받은 메시지를 **해석하지 말고 그대로** ROS 토픽으로 발행만 하면 됩니다.

```
토픽: /server/inbound
타입: std_msgs/String     (받은 JSON 문자열 그대로)
```

- 내용 판단은 Nav2 쪽 노드에서 합니다
- 서버→젯슨 메시지가 나중에 늘어나도 **이 통로 하나로 다 처리**되니 재작업 없음
- 기존 송신 로직은 그대로 두면 됩니다

서버는 이런 형태로 보냅니다.

```json
{"event_type": "event_ack"}
```

## 전체 흐름

```
[프론트]  "확인" 클릭
    │  {"event_type": "event_ack"}     기존 /ws/frontend 소켓
    ▼
[백엔드]  젯슨으로 그대로 배달           ✅ 완료
    │
    ▼
[젯슨]    websocket_client.py 수신
    │  → /server/inbound 로 발행        ← 주현 담당
    ▼
[Nav2]    event_ack 확인 → 순찰 재개     ← 정기 담당
```

상세 스펙은 `docs/interface.md` ⑧번 항목에 있습니다.
