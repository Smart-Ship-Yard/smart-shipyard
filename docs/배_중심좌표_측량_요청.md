# 배(모형) 중심좌표 측량 — `ship_survey_node` 요청

2026-08-14 · 요청: 이정기 (Nav2 · 백엔드) → 담당: 이주현 (젯슨 · SLAM · YOLO)

---

## 한 줄 요약

**YOLO로 배를 인식해 표면점을 모으고, 그걸로 배의 중심좌표와 방향을 계산해서
`/ship_survey/pose` 로 한 번 발행해주는 노드**를 하나 만들어주세요.

---

## 왜 필요한가

Nav2가 "배 주위를 원형으로 순찰"하려면 **배의 중심좌표**가 있어야 합니다.
지금은 맵에서 자동으로 찾고 있는데, 이 방법이 우리 배에는 통하지 않습니다.

라이다가 바닥에서 약 21 cm 높이의 **수평면 한 장**만 스캔하는데,
모형 배는 그 높이에 선체가 걸리지 않습니다. 즉:

- **맵에 배가 안 찍힘** → 순찰 중심을 자동으로 찾을 수 없음
- **코스트맵도 배를 모름** → Nav2가 배를 빈 공간으로 알고 가로질러 갈 수 있음

임시로는 매핑할 때 배 자리에 높은 상자를 놓는 방법이 있지만,
**뎁스카메라로 직접 측량하는 쪽이 정석**이라 이 요청을 드립니다.

---

## 만들 것 — `ship_survey_node`

### 입력

```
/event_detection/uvd   (std_msgs/String, JSON)
```

`yolo_depth_publisher`가 이미 발행하고 있는 그 토픽입니다.
`class_id`가 배에 해당하는 것만 골라서 쓰면 됩니다.

### 처리 (방향성만 — 구체적 수치는 직접 판단해주세요)

1. 검출마다 나오는 `depth_xyz`를 **map 좌표로 변환**해서 누적합니다.
   - 이 값은 카메라를 향한 **표면의 한 점**입니다. 배 중심이 아닙니다.
   - 그래서 한 프레임으로는 중심을 알 수 없고, **여러 각도에서 모아야** 합니다.
2. 매핑하며 로봇이 배 주위를 한 바퀴 돌면 점들이 배 둘레에 흩뿌려집니다.
3. 그 2D 점 집합에 **도형을 피팅**해서 중심과 방향을 뽑습니다.
   - `cv2.minAreaRect` 를 쓰면 중심·크기·회전각이 한 번에 나옵니다.
     (`yolo_depth_publisher.py`에 `import cv2`가 이미 있어 새 의존성 없음)
   - 단순 평균(centroid)은 많이 본 쪽으로 치우치므로 권하지 않습니다.
4. 점이 충분히 모이고 한 바퀴가 끝났다고 판단되면 **한 번 확정**합니다.

### 출력 ①: 토픽

```
/ship_survey/pose      (std_msgs/String, JSON)
```

내용은 `docs/interface.md` ④번 스펙 그대로:

```json
{"event_type": "ship_pose", "block_id": "B1", "map_xy": [5.1, 4.8], "yaw": 1.57}
```

`websocket_client.py`가 이 토픽을 **이미 구독하고 있습니다**
(`ship_pose_input_topic` 파라미터). 발행만 해주시면 서버·프론트까지 자동으로 흘러갑니다.

### 출력 ②: 파일 — ★ 여기엔 `size_xy` 를 하나 더 넣어주세요

```
/tmp/ship_survey_results/ship_pose_<회차>.json
```

```json
{"event_type": "ship_pose", "block_id": "B1",
 "map_xy": [5.1, 4.8], "yaw": 1.57,
 "size_xy": [0.76, 0.14]}
```

**`size_xy` 는 배의 가로·세로 크기(m)** 입니다. `cv2.minAreaRect` 가
중심·각도와 함께 돌려주는 값이라 추가 계산이 없습니다.

왜 필요한가 — Nav2 쪽에서 이 값으로 **keepout 마스크**를 만듭니다. 배가
라이다에 안 잡히니 맵에서 크기를 알아낼 방법이 없어서, 이 값이 없으면
"배가 어디 있는지는 아는데 얼마나 큰지 몰라" 마스크를 못 만듭니다.
그러면 Nav2 가 배를 여전히 빈 공간으로 알고 가로지를 수 있습니다.

> 웹소켓으로 보내는 메시지(출력 ①)에는 넣지 않아도 됩니다.
> `interface.md` 스펙을 바꾸지 않기 위해 **파일에만** 추가해주세요.

토픽만으로는 나중에 자율주행할 때 값이 사라집니다.
**캘리브레이션·정합 결과와 똑같은 방식**으로 파일에도 남겨주세요.

```
/tmp/uwb_calibration_results/calib_001.json      ← 기존
/tmp/slam_map_alignment_results/align_001.json   ← 기존
/tmp/ship_survey_results/ship_pose_001.json      ← 추가할 것
```

Nav2 쪽 `finalize_map.py`가 이 파일을 읽어서 레포에 보존하고 순찰 설정에 반영합니다.
(그 스크립트는 ROS 노드가 아니라 평범한 파이썬 스크립트여서 토픽을 못 받습니다.
그래서 파일이 필요합니다.)

## ⚠️ 주의사항

### 1. `/event_detection/map_point` 를 쓰면 안 됩니다

`change_point.py`의 출력인데, 여기엔 **중복 제거 로직**이 들어 있습니다
(`_find_matching_event` → "중복 이벤트로 판단"). 같은 배를 반복 관측한 것이
걸러져서 점이 거의 안 쌓입니다.

측량은 점이 많을수록 정확하므로 **원본 `/event_detection/uvd`를 직접 구독**해주세요.

### 2. `TRANSIENT_LOCAL` QoS 를 명시적으로 설정해야 합니다

ROS 2 기본값은 `VOLATILE`이라 **자동으로 되지 않습니다.** 그냥 발행하면
나중에 구독을 시작한 노드는 값을 영영 못 받습니다.

이 프로젝트에서 쓰는 방식 (`ship_ugv_navigation/event_gate_node.py:95`):

```python
from rclpy.qos import QoSProfile, QoSDurabilityPolicy, QoSReliabilityPolicy

qos = QoSProfile(depth=1,
                 durability=QoSDurabilityPolicy.TRANSIENT_LOCAL,
                 reliability=QoSReliabilityPolicy.RELIABLE)
```

이렇게 하면 **한 번만 발행해도** 나중에 붙는 구독자가 마지막 값을 받습니다.
재접속 시 재전송 로직을 따로 짤 필요가 없습니다 — ROS가 처리합니다.

### 3. 계속 발행하지 마세요 — 측량 끝나면 1회

`interface.md` ④번에도 "세션 시작 측량 후 1번 + 조립 단계 변경 시마다 1번"으로
정의돼 있습니다. 계속 갱신하면 Nav2 쪽에서 코스트맵과 경로가 매 순간
무효화되어 로봇이 진동합니다.

### 4. ★ `yaw` 는 `size_xy` **첫 번째 값(가로)** 의 축 방향이어야 합니다

이게 어긋나면 마스크가 90도 돌아가 **배를 통째로 빗나갑니다.**

```
size_xy = (0.76, 0.14) 로 보냈는데 yaw 가 짧은 축(0.14)을 가리키면
  → 14 x 76 짜리 마스크가 그려짐 → 실제 배는 마스크 밖에 있음
```

`cv2.minAreaRect` 반환값을 그대로 쓰면 맞습니다:

```python
(cx, cy), (w, h), angle = cv2.minAreaRect(pts)
#  map_xy  = [cx, cy]
#  size_xy = [w, h]        ← 이 순서 그대로
#  yaw     = radians(angle) ← w 축의 방향
```

Nav2 쪽 `rect_bbox()` 가 `size_xy[0]` 을 `yaw` 방향 축으로 두고 사각형을
그리므로, 위 대응만 지키면 됩니다.

> **뱃머리가 어느 쪽인지는 몰라도 됩니다.** 직사각형이라 180도 뒤집혀도
> 마스크 영역은 같습니다. 다만 프론트의 3D 배 모델 방향은 영향을 받습니다
> (아래 참고).

### 5. `localization.launch.py` 에 넣어주세요

`yolo_depth_publisher`와 함께요. 지금 `yolo_depth_publisher`는 launch에 없어서
따로 실행해야 하는데, **측량은 매핑할 때 같이 이뤄져야** 하므로
매핑 전에 켜지는 launch에 둘 다 들어가는 게 맞습니다.

```
매핑 랩 1회
  ├─ SLAM        → 맵 생성
  └─ 측량 노드   → 배 중심좌표      ← 같은 주행으로 동시에
```

Nav2를 켠 뒤에 측량하면 순서가 꼬입니다. 순찰을 돌려면 중심이 이미 있어야 하는데,
중심을 구하려고 도는 것이라 닭-달걀이 됩니다.

## 참고 — 프론트 3D 모델의 뱃머리 방향 (Nav2 와 무관)

`interface.md` ④번의 `yaw` 는 프론트가 3D 배 모델을 배치하는 데 쓰입니다.
그런데 `cv2.minAreaRect` 로 구한 각도는 **직사각형의 축 방향**이라
**180도 모호함이 남습니다** — 어느 쪽이 뱃머리인지는 구분되지 않습니다.

```
      yaw = 30°                    yaw = 210°
   ╱▔▔▔▔▔▔▔╲                    ╱▔▔▔▔▔▔▔╲
  ◤ 뱃머리      ◥              ◤      뱃머리 ◥
   ╲_________╱                  ╲_________╱
            직사각형으로는 이 둘이 같다
```

**Nav2 쪽은 이 모호함이 무해합니다** (마스크 영역이 같음). 다만 프론트에서
배가 180도 돌아 보일 수 있으니, 담당이신 만큼 한 번 확인해주시면 좋겠습니다.

푸는 방법은 여러 가지가 있고 무엇을 골라도 됩니다:

- **형상 비대칭 이용** — 뱃머리 쪽이 좁습니다. 장축을 따라 점들의 폭 분포를
  보면 좁은 쪽이 뱃머리입니다. 포인트클라우드를 쓰신다면 몇 줄이면 됩니다
- **한 번 고정** — 배를 세션 중에 돌리지 않으므로, 뒤집혀 보이면 180도를
  더해 보내는 식으로 한 번만 맞춰도 됩니다
- **YOLO 클래스 분리** — 학습 비용이 있어 지금은 권하지 않습니다

급한 항목은 아닙니다. 시연 화면에서 배가 뒤집혀 보이면 그때 잡아도 됩니다.

## Nav2(이정기) 쪽에서 할 일 — ✅ **이미 다 되어 있습니다**

측량 결과를 받은 뒤는 전부 이쪽에서 처리합니다. 신경 쓰지 않으셔도 됩니다.
**아래는 계획이 아니라 구현·검증이 끝난 상태입니다.**

- `finalize_map.py` 가 `/tmp/ship_survey_results/ship_pose_*.json` 을 읽어
  순찰 중심에 반영 (없으면 맵에서 자동 탐지로 조용히 넘어감)
- 그 좌표와 `size_xy` 로 **keepout 마스크** 자동 생성
- `navigation.launch.py` 가 마스크가 있으면 `KeepoutFilter` 를 글로벌·로컬
  코스트맵 양쪽에 붙임 → 라이다가 못 봐도 Nav2 가 배를 가로지르지 않음
- 배 바깥 원을 따라 도는 순찰도 구현·검증 완료 (`patrol_mission_node`)

**즉 `/ship_survey/pose` + `ship_pose_*.json` 만 나오면 그 뒤는 자동입니다.**

## 확인 방법

배 학습이 끝난 뒤, 매핑 랩을 한 바퀴 돌고:

```bash
# 값이 나오는지
ros2 topic echo /ship_survey/pose --once

# 나중에 구독해도 받아지는지 (latched 확인 — 위 명령을 한참 뒤에 다시 실행)
ros2 topic echo /ship_survey/pose --once

# 파일로 남았는지
ls /tmp/ship_survey_results/
```

`map_xy`가 실제 배 위치와 대충 맞는지는 RViz에서 맵 위 좌표와 비교하면 됩니다.
