# Backend — 실시간 이벤트 중계 서버

스마트 조선소 디지털 트윈 시스템의 백엔드 서버입니다.
젯슨(UGV)이 보내는 실시간 위치/이벤트 데이터를 받아 프론트엔드 대시보드에 중계하고,
위험 이벤트를 MongoDB에 기록합니다.

담당: 이정기 (Backend & Streaming Engineer)

## 기술 스택

| 구분 | 기술 |
|---|---|
| 프레임워크 | FastAPI (Python 3.10+) |
| 실시간 통신 | WebSocket |
| DB | MongoDB Atlas (motor 비동기 드라이버) |
| 실행 서버 | Uvicorn |

## 처리하는 이벤트 4종

| event_type | 의미 |
|---|---|
| `ship_defect` | 선박(블록) 결함 |
| `no_helmet` | 안전모 미착용 |
| `fallen_person` | 작업자 쓰러짐 |
| `fire` | 화재 |

위 4종만 MongoDB에 영구 저장되며, 그 외 메시지(위치 핑 등)는 저장 없이 프론트엔드로 중계만 됩니다.

## 실행 방법

```bash
cd ~/smart-shipyard/backend

# 1. 가상환경 생성 및 활성화 (최초 1회)
python -m venv venv
source venv/bin/activate      

# 2. 패키지 설치
pip install -r requirements.txt

# 3. 환경 변수 설정 (최초 1회)
cp .env.example .env
# .env 파일을 열어 MONGO_URL에 실제 접속 주소 입력

# 4. 서버 실행 (팀 연동용 — 0.0.0.0 이 핵심)
venv/bin/uvicorn main:app --host 0.0.0.0 --port 8000
```

**`--host 0.0.0.0` 을 반드시 붙입니다.** 생략하면 `127.0.0.1` 에만 묶여
**이 노트북 안에서만** 접속됩니다. 젯슨·프론트엔드는 같은 공유기의 다른
기기라서 연결이 안 됩니다.

> `--reload` 는 파일을 저장할 때마다 서버를 재시작하는 옵션이라 혼자
> 코드를 고칠 때만 씁니다. 젯슨이 붙어 있는 상태에서 켜두면 연동 중에
> 연결이 끊겼다 붙었다 합니다.

서버가 뜨면 http://127.0.0.1:8000/docs 에서 API 문서를 확인할 수 있습니다.
팀에 공유하는 주소는 `ws://<이 노트북 LAN IP>:8000/ws/...` 입니다
(`hostname -I` 로 확인).

## 대시보드 재접속 시 위험 핑 복원

브라우저를 **새로고침해도 화면의 위험 핑이 그대로 남는다.** 대시보드가
`/ws/frontend` 에 접속하면 서버가 **아직 살아있는 위험 이벤트**를 그 소켓에만
다시 보내준다 (다른 대시보드에는 안 보낸다 — 보내면 핑이 중복 생성된다).

- 순서: **`ship_pose` 를 먼저** 보낸다. 프론트가 `map_xy` → 구획 좌표로 바꿀 때
  배 위치가 필요한데, 없으면 핑이 엉뚱한 자리에 찍힌다.
- 복원분에는 `replay: true` 가 붙는다. 프론트는 이 표시를 보고 **핑은 그리되
  팝업은 띄우지 않는다.** 안 그러면 새로고침할 때마다 팝업이 연달아 뜬다.
- "살아있다"의 판정은 **젯슨이 보낸 `event_cleared` 가 왔는지**로만 한다.
  로봇이 그 자리를 다시 지나가 "이제 안 보인다"를 확인해야 오는 신호다.

### ⚠️ 시간대를 섞지 말 것 (2026-08-28 버그)

복원 판정은 `timestamp` **ISO 문자열의 사전순 비교**입니다. 문자열 비교는
`+09:00` / `+00:00` 같은 시간대 표기를 읽지 않습니다.

```
"2026-08-28T22:23+09:00"  >=  "2026-08-28T14:23+00:00"   →  True  (문자열)
                                                          →  False (실제 시각)
```

바닥을 UTC 로 잡았더니 **9시간 뒤로 밀려**, 서버 켜기 직전 9시간의 이벤트가
전부 되살아났습니다. 대시보드에 유령 핑이 뜬 원인이 이것입니다.

`RESTORE_FLOOR_AT` 은 저장할 때와 같은 **KST** 로 잡습니다. 그래야 사전순
비교가 곧 시간순 비교가 됩니다.

### ⚠️ 서버를 다시 켜면 이전 핑은 전부 초기화된다

복원 대상은 **서버 프로세스가 켜진 시각 이후에 들어온 이벤트뿐이다**
(`RESTORE_FLOOR_AT`). 이 값은 서버가 켜질 때뿐 아니라 대시보드의 **[🧹 초기화]**
(`reset_events`)로도 지금 시각으로 밀립니다 — 그래서 이름이 "서버 시작 시각"이
아닙니다. 서버를 재시작하면 그 전에 있던 핑은 대시보드에서
사라지고, 새로고침해도 다시 뜨지 않는다.

**젯슨은 그것들을 다시 보내주지 않는다.** `change_point_detector` 가 이미 보고한
이벤트를 재발행하지 않기 때문이다(같은 자리 불로 로봇이 반복 정지하는 것을
막는 핵심 로직이라 그대로 두어야 한다). 그러므로 **시연 중에는 백엔드를
재시작하지 않는 것이 좋다.**

> **왜 이렇게 했나** — `event_cleared` 가 한 번이라도 안 오면 그 이벤트는 영원히
> "살아있는" 것으로 남는다. 이 제한을 넣기 전 DB 에는 복원 대상이 56건 있었고
> 그중 46건이 하루 이상 된 것이었다. 옛 좌표의 불을 로봇이 다시 지나갈 일이
> 없어 `event_cleared` 가 올 수 없고, 젯슨 쪽 clear 로직을 고쳐도 이미 쌓인
> 것은 그대로 남는다. 서버를 다시 켰다는 것은 "여기서부터 새로 본다"는 뜻이므로
> 그 시각을 바닥으로 깔았다.

## 영상은 이 서버(FastAPI)를 거치지 않는다

같은 노트북에서 도는 **별개 프로세스인 mediamtx** 가 받습니다.
젯슨이 H.264 로 **한 번만** 인코딩해 `rtsp://192.168.0.5:8554/ugv1` 로 밀어올리고,
브라우저들은 `http://192.168.0.5:8889/ugv1` 에 WebRTC 로 붙습니다.

```
젯슨 ──H.264 1개, RTSP push──▶ mediamtx(같은 노트북) ──WebRTC──▶ 브라우저 N명
```

설치·방화벽·검증은 [`server/streaming/README.md`](../server/streaming/README.md).

> **P2P 가 아닙니다.** mediamtx 가 미디어 서버이고 브라우저가 거기 접속하는
> client-server 구조입니다. WebRTC 를 쓸 뿐 양쪽이 대등하지 않습니다.

> **포트가 겹쳐 보이는 것** — `ss -lntup` 에서 mediamtx 가 UDP 8000 을 잡고 있습니다.
> 이 백엔드는 TCP 8000 이라 서로 다른 소켓이고 충돌하지 않습니다.

### 제약은 CPU 였습니다

젯슨 6코어에서 **Nav2 자율주행 · YOLO 추론 · 영상 송출을 동시에** 돌려야 했습니다.
CPU 가 포화되면 Nav2 의 lifecycle 전환이 타임아웃되고, 그러면 자율주행이 통째로
실패합니다. **실제로 겪었습니다.**

그래서 영상 경로에 **인코딩을 한 번만 두는** 구조를 택했습니다.
실측으로 영상 전체가 **0.43 코어**입니다.

백엔드로 중계하려면 MJPEG 로 보내야 해서 프레임 간 압축이 사라집니다.
대역폭이 3~5배가 되고 혼잡 제어가 없어집니다 — 네트워크가 밀리면 프레임이 쌓여
지연이 눈덩이처럼 커지는데, WebRTC 는 스스로 화질을 낮춰 버팁니다.

**거치는 게 나쁜 게 아니라 MJPEG 로 거치는 게 나쁩니다.**
H.264 를 유지한 채 중앙 미디어 서버로 밀어올리는 구조가 정답이고, 그게 다음 단계입니다.

### 팬아웃은 이제 서버가 합니다 (2026-08-28)

옮기기 전에는 젯슨이 **시청자마다** 스트림을 뿌려서, 시청자가 늘면 로봇이
부담을 졌습니다. 지금은 젯슨이 몇 명이 보든 스트림 **하나만** 올립니다.
젯슨 쪽은 코드 변경 없이 systemd 환경변수 한 줄로 끝났습니다.

**여전히 단일 LAN 데모 구성입니다.** 관제실이 다른 망에 있으면 접속이 안 됩니다.
외부망 수단이 없어서가 아닙니다 — ngrok 계정으로 받아둔 외부 주소가 있지만
**지금 만드는 것이 데모 버전이라 거기까지 확장하지 않았습니다.** 원격 관제로
가는 시점에는 이 mediamtx 를 외부에서 닿는 곳에 두고 인증을 붙이면 됩니다.

> **백엔드에 영상 폴백 경로는 없습니다.** 예전의
> `/ws/jetson-stream` → `/ws/frontend-stream` 과 `stream_boost` 는 **2026-08-28
> 삭제했습니다.** 젯슨이 그 창구로 프레임을 보낸 적이 한 번도 없어 "폴백"이라
> 적혀 있었을 뿐 실제로는 동작하지 않았습니다 — 시연 중에 전환했다면 검은 화면만
> 나왔을 것입니다. 영상이 안 나오면 mediamtx 와 방화벽을 봅니다.

## 접근 암호 (선택)

`.env` 에 `DASHBOARD_PASSWORD` 를 넣으면 대시보드와 조회 API 가 잠깁니다.

```
DASHBOARD_PASSWORD=원하는암호
```

> ### 비워두면 지금까지와 똑같이 동작합니다
>
> 값이 없으면 인증을 **아예 하지 않습니다.** 팀원이 각자 노트북에서 받아 그대로
> 실행할 수 있어야 하고, 시연 직전에 암호 때문에 화면이 안 뜨는 상황을 만들면
> 안 되기 때문입니다. **현장 적용 전에는 반드시 설정하세요** — 안 걸면 같은 망의
> 누구나 관제 화면을 봅니다.

| | |
|---|---|
| 방식 | 계정이 아니라 **팀이 공유하는 암호 하나** |
| 로그인 | `POST /api/login {"password": "..."}` → 토큰 |
| 토큰 전달 | 쿼리스트링 `?token=...` (브라우저 WebSocket 이 헤더를 못 붙임) |
| 보관 | 서버 메모리 — 재시작하면 다시 로그인 |
| 잠기는 것 | `/ws/frontend`, `/api/init-data`, `/api/events`, `/api/event-days` |

- 암호 비교는 `secrets.compare_digest` 로 **같은 시간**이 걸리게 합니다.
  `==` 는 다른 글자에서 즉시 멈춰 응답 시간 차이로 암호를 한 글자씩 알아낼 수
  있습니다(타이밍 공격)
- **반드시 바이트로 비교합니다.** `compare_digest` 는 비ASCII 문자열을 받으면
  `TypeError` 를 냅니다 — 한글 암호나 한글 오타 입력에서 500 이 나갔습니다(실측)

### mediamtx 위임은 아직 안 붙였습니다

`/api/mediamtx-auth` 자리는 잡아뒀지만 켜지 않았습니다. 브라우저가 mediamtx 에
**직접** 붙으므로 토큰을 어떻게 실어 보낼지를 먼저 정해야 합니다
([`server/streaming/README.md`](../server/streaming/README.md) 참고).

## 감지 순간 사진 (스냅샷)

젯슨이 위험 이벤트를 보낸 **직후**, 그 순간의 잘라낸 사진을 `event_snapshot`
메시지에 base64 로 실어 보냅니다. 대시보드에서 핑을 눌렀을 때 "그때 무슨 일이
있었나"를 보여주기 위한 것입니다.

```
젯슨 ──image_b64──▶ 서버 ──파일──▶ backend/snapshots/<event_id 해시>.jpg
                     │
                     ├─ 몽고: 그 event_id 의 위험 이벤트 문서에 image_url 만 추가
                     └─ 프론트: image_url 만 담은 가벼운 메시지 (base64 없음)
```

**base64 를 DB 에 넣지도, 프론트로 흘리지도 않습니다.** 복원은 이벤트 문서를
그대로 다시 보내는 구조라, 문서에 사진이 들어 있으면 새로고침할 때마다 살아있는
이벤트의 사진이 전부 다시 흐릅니다. URL 이면 브라우저가 캐시해 두 번째부터는
받지 않습니다.

### 영상이 있는데 왜 사진을 따로 보내나

영상은 **지금 흐르는 화면**이고, 사진은 **그때 무슨 일이 있었는지**입니다.
관제사가 나중에 핑을 눌렀을 때 필요한 건 후자입니다.

부하도 문제되지 않습니다. **중복 제거를 통과한 새 이벤트에 대해서만** 인코딩해서
이벤트 한 건당 **1.4 ms** 입니다. 영상이 이미 초당 5~15장을 인코딩하고 있으니
비교가 안 되는 양입니다.

> ⚠️ 순서가 중요합니다 — **중복 제거를 통과한 뒤에** 인코딩해야 합니다.
> 매 프레임 인코딩하고 나서 버리면 초당 수십 번이 되어 얘기가 완전히 달라집니다.

**확인은 몽고 창이 아니라 브라우저로 합니다** — 몽고에는 주소밖에 없습니다.

```
http://192.168.0.5:8000/snapshots/<해시>.jpg
```

### ⚠️ 사진은 절대 커밋하지 마세요

작업자 얼굴이 찍힐 수 있습니다. `.gitignore` 가 막고 있습니다.

```
backend/snapshots/*          ← 사진 전부 차단
!backend/snapshots/.gitkeep  ← 폴더만 남김
```

폴더째 무시하지 않고 `.gitkeep` 을 남기는 이유는, 새로 clone 했을 때 폴더가
없으면 `StaticFiles(directory=...)` 가 폴더를 못 찾아 **서버가 시작조차 못 하기**
때문입니다. (`main.py` 의 `os.makedirs(..., exist_ok=True)` 가 한 겹 더 막아줍니다.)

사진은 한 장에 20~40KB, 한 세션에 많아야 20건이라 100 세션을 돌려도 60MB 정도입니다.
용량보다 얼굴 쪽이 훨씬 중요한 이유입니다.

## API 요약

| 종류 | 경로 | 설명 |
|---|---|---|
| WebSocket | `/ws/jetson` | 젯슨(UGV)이 데이터를 보내는 채널 |
| WebSocket | `/ws/frontend` | 대시보드가 실시간 알림을 받는 채널 |
| GET | `/snapshots/<해시>.jpg` | 감지 순간 사진 (정적 파일, 위 항목 참고) |
| GET | `/api/init-data` | 대시보드 초기 3D 맵 정보 |
| GET | `/api/event-days` | 이벤트가 있었던 날짜와 건수 (최신순 60일) |
| GET | `/api/events?date=YYYY-MM-DD` | 그날의 위험 이벤트 + 사진 URL + 치워진 시각 |
| GET | `/api/history` | 과거 이벤트 로그 조회 (최근 50건, 종류 구분 없음) |

영상 채널은 없습니다 — 영상은 이 서버를 거치지 않습니다 (위 항목 참고).

## 젯슨 → 서버 메시지 형식

> **정본은 [`docs/interface.md`](../docs/interface.md) 입니다.** 아래는 발췌이며,
> 키 이름·타입이 이 문서와 다르면 `docs/interface.md` 쪽이 맞습니다.

위험 이벤트 (② — DB 저장 대상):

```json
{
  "event_type": "fire",
  "confidence": 0.92,
  "map_xy": [0.63, -0.23],
  "ekf_global": [3.2, 7.8],
  "event_id": "fire@0.63,-0.23"
}
```

위치 핑 (① — DB 저장 안 함, 0.5초 주기):

```json
{"event_type": "position", "ekf_global": [3.2, 7.8]}
```

- `event_type` — 위험 이벤트 허용 값 4개: `fallen_person` · `fire` · `no_helmet` · `ship_defect`
- `confidence` — YOLO conf 그대로 (0.5~1.0)
- `map_xy` — **map 기준** 객체 절대좌표 `[x, y]`, 미터. 젯슨이 TF 변환까지 끝내서 보냅니다.
  (v1.6 이전에는 카메라 상대좌표 `depth_xyz` 를 보냈습니다. 지금은 오지 않습니다.)
- `event_id` — `"<클래스>@<x>,<y>"`. 나중에 `event_cleared` 로 이 핑만 콕 집어 지울 때 씁니다.
- `ekf_global` — **map 기준** 차체 절대좌표 `[x, y]`, 미터. ekf_global(EKF 융합) 출력값이다.
  UWB 원시좌표(`uwb_frame`)가 아니라 EKF가 map으로 변환·융합한 뒤의 값이므로,
  서버·프론트는 추가 좌표변환 없이 그대로 쓰면 됩니다.
- `timestamp` — 서버가 붙이므로 젯슨은 보내지 않습니다.

나머지 메시지(②-b `event_cleared`, ②-c `event_snapshot`, ③ `block_level`,
④ `ship_pose`, ⑦ `webrtc_signal`, ⑧ `event_ack`)와 전체 필드 표는
`docs/interface.md`를 참고하세요.

> ⚠️ 서버는 모르는 `event_type`을 에러 없이 조용히 무시합니다. 철자를 반드시 위 표에서
> 복사해 쓰세요 — 오타가 나면 아무 일도 일어나지 않아 디버깅이 어렵습니다.
